# Factory — short-lived verification codes

**Owner: Partho**

## The problem this solves

Renki shows short-lived codes on screen in two places: confirming a friendship
in person, and starting a ride. Same idea, same 30-second life, same job — a
code shown on a phone and read by another phone's camera.

They are generated by **two different pieces of code, and those have already
drifted apart**:

```
src/services/friendship.service.ts:626
  '23456789ABCDEFGHJKMNPQRSTVWXYZ'    30 characters — no I, L, O, U

src/services/ride-lifecycle.service.ts:51
  'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'  32 characters — no I, O, but HAS L and U
```

Different alphabets. Different lengths. A third scheme again in
`services/qr-verification.service.ts`, using base64url.

This is not a style nitpick. These codes get read off a **glossy screen by a
camera at arm's length**. One alphabet carefully removes the characters people
and cameras confuse — `I`/`1`, `L`/`1`, `O`/`0`, `U`/`V`. The other lets `L` and
`U` through. One of them is more likely to be misread, and nobody decided that;
it happened because the second was written separately from the first.

`CLAUDE.md` says the two features were given matching database columns
_"precisely so the two features could not drift into two sets of rules."_ The
**schema** stayed in step. The **code** did not.

## What a Factory is, in one sentence

A Factory is a single place that knows how to build a thing, so callers ask for
one instead of assembling it themselves. Here: one place that knows how to make
a short-lived code, so nobody writes an alphabet by hand ever again.

## Step 1 — the product

`verification-code.ts`

```ts
/** The two things a short-lived code is used for. */
export type CodeKind = 'friend-meetup' | 'ride-start';

/** What the factory hands back. */
export interface VerificationCode {
  code: string;
  expiresAt: Date;
  /** Seconds this code is good for. The client counts down from this. */
  ttlSeconds: number;
}
```

## Step 2 — the factory

`verification-code.factory.ts`

```ts
import { randomBytes } from 'node:crypto';
import type { CodeKind, VerificationCode } from './verification-code.js';

/**
 * One alphabet, decided once.
 *
 * No I, L, O, U, 0 or 1. These are read off a glossy screen by a camera at
 * arm's length, and every one of those characters is confusable with another.
 */
const ALPHABET = '23456789ABCDEFGHJKMNPQRSTVWXYZ';

const CODE_LENGTH = 10;

/** Per-kind settings. Adding a third kind is one line here. */
const TTL_SECONDS: Record<CodeKind, number> = {
  'friend-meetup': 30,
  'ride-start': 30,
};

export class VerificationCodeFactory {
  create(kind: CodeKind): VerificationCode {
    const ttlSeconds = TTL_SECONDS[kind];
    return {
      code: this.generate(),
      expiresAt: new Date(Date.now() + ttlSeconds * 1000),
      ttlSeconds,
    };
  }

  private generate(): string {

  }
}

export const verificationCodeFactory = new VerificationCodeFactory();
```

**Use `randomBytes` from `node:crypto`, never `Math.random()`.** A guessable
code defeats the entire point — the whole security model of this feature is that
you cannot produce a valid code without being in the room.

> **Why `TTL_SECONDS` is a map rather than one constant:** both are 30 today, and
> they are 30 for slightly different reasons. Keeping them as separate entries
> means changing one later is a one-line edit in a visible place, rather than
> someone discovering the shared constant and reintroducing the drift from the
> other direction.

## Step 3 — the two call sites

**A. `src/services/friendship.service.ts`**

- Find `issueMeetupCode` (~line 576) and `generateMeetupCode` /
  `CODE_ALPHABET` / `CODE_LENGTH` (~line 626)
- Replace `const code = generateMeetupCode();` with a call to the factory
- The INSERT currently computes expiry in SQL with
  `now() + make_interval(secs => $4)`. You may keep that and pass
  `ttlSeconds`, or pass `expiresAt` directly. **Keeping the SQL version is
  safer** — it uses the database's clock, so a server whose clock is a few
  minutes out cannot issue a code that is already dead.
- Delete `generateMeetupCode`, `CODE_ALPHABET` and `CODE_LENGTH`

**B. `src/services/ride-lifecycle.service.ts`**

- Find `issueStartCode` (~line 60) and `generateCode` / `ALPHABET` (~line 51)
- Same replacement
- Delete `generateCode` and `ALPHABET`

Leave `MEETUP_CODE_TTL_SECONDS` and `RIDE_START_CODE_TTL_SECONDS` exported where
they are — the frontend and the tests import them. Have the factory be the
source of truth and those constants read from it, **or** leave them as-is and
have the factory read them. Either is fine; say which in a comment. What must
not happen is two numbers that can disagree.

**Do not touch `services/qr-verification.service.ts`.** It is a separate,
older thing with its own tests. Fold it in only if everything else passes and
you have time.

## Traps

- **`Math.random()` is not acceptable here.** `randomBytes` only.
- **Do not change the code length without checking the column.** Both `code`
  columns are `VARCHAR(64)`, so 10 is fine, but check before going longer.
- **Do not remove characters until only a few remain.** A 30-character alphabet
  at length 10 is about 49 bits — plenty. Cutting the alphabet to 20 to be extra
  safe makes codes easier to guess, not harder.
- **Do not "simplify" the two TTL constants into one.** See Step 2.
- Remember the `.js` extension on every relative import.
